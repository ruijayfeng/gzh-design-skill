# 词员外公众号内容风格排版方案 V1

## 使用约定

最简调用：

> 用词员外风格排版这篇文章：`文章文件或正文`

该主题只负责公众号视觉排版，不参与选题、写作、改写、润色、总结或配图生成。标题、正文、结论、署名、CTA 和图片均以输入内容为准；原文没有的内容不补。允许增加的文字仅限“左右滑动查看”“上下滑动查看”等操作提示。

## 1. 核心定位

主题名称：**词员外·现代水墨**  
英文标识：`theme-ciyuanwai-ledger`

一句话定位：

> 面向大众的现代内容排版 × 词员外水墨视觉识别。

这不是“国风 AI 公众号”，也不要求读者理解一套账房术语。文章标题、章节、提示、结论和列表主要使用大众熟悉的现代中文；“员外一句”这类有记忆点的签名可以低频保留。词员外的 IP 感更多通过暖白、墨线、朱砂、印章、宋体标题和水墨插图体现。需要配图时，才把抽象概念转换成词员外参与的视觉动作。

核心比例：

- 60% 现代知识编辑设计：清晰标题、现代正文、稳定行距和层级。
- 30% 词员外水墨隐喻：正文插图、章节转折和核心认知锚点。
- 10% 中国传统识别元素：朱砂印、墨线、少量宋体标题。

## 2. 视觉 DNA

### 色彩

| 角色 | 色值 | 用途 |
|---|---|---|
| 墨色 | `#2B2B28` | 一级标题、深色结论、主要边框 |
| 宣纸暖白 | `#F8F3E8` | 全局背景 |
| 正文色 | `#3F403B` | 正文阅读 |
| 朱砂红 | `#C0392B` | 章节标签、关键词下划线、印章、警示 |
| 暖灰浅底 | `#F1E9DC` | 补充说明、步骤和轻量卡片 |
| 旧纸边线 | `#D8CDBC` | 分隔线、弱边框 |
| 靛青 | `#3B5998` | 信息说明与冷静状态，低频使用 |
| 赭石 | `#B9770E` | 数据和进度提示，低频使用 |

配色纪律：朱砂只用于关键标记，不大面积铺底；靛青和赭石不能同时成为第二主色；正文约 85% 由墨色与中性灰承担。

### 字体

- 正文：系统黑体，保持现代和易读。
- 主标题、金句、结论：宋体或系统衬线字体，增加文人感。
- 英文标签：系统无衬线字体，只作为小号辅助信息。
- 代码：系统等宽字体。

正文不使用仿古文案，不强行写成说书或章回体。词员外负责视觉翻译，不负责把现代中文改成古文。

### 形态

- 直角和 2—6px 小圆角为主。
- 基本不使用阴影，以墨线、细边框和留白分层。
- 不使用祥云、龙纹、金色、大红宫廷边框等商业国风符号。
- 不使用大面积纸张噪点，纸感主要来自底色和插图本身。

## 3. 内容语言原则

内容标签全部使用大众熟悉的表达：

| 标签 | 用途 |
|---|---|
| 内容导读 | 展示三个核心看点 |
| 核心观点 | 全文最重要的判断 |
| 事实核验 | 数据、来源与证据说明 |
| 尚待确认 | 尚未得到验证的信息 |
| 核心结论 | 值得记住和复用的结论 |
| 常见误区 | 错误理解和失败判断 |
| 补充说明 | 不打断正文的旁注 |
| 执行流程 | 步骤和操作路径 |
| 全文总结 | 收束文章并给出下一步 |

签名标签：

| 标签 | 用法 |
|---|---|
| 员外一句 | 作者的一句判断、经验或有人味的收束 |

“员外一句”是可选签名，一篇最多 1 次，且真正有一句值得记住的话时才用。“词员外”“词元”等品牌文字可出现在封面栏目、图片角色、作者区、员外一句和尾部印章，但不形成一整套角色术语。

### 参考阿真 Irene 的“舒服感”

学习她的表达节奏，不复制她的具体视觉：

- 开头先像朋友聊天：一句问候，一个真实场景，再说这篇要解决什么。
- 允许适量口语、自嘲和小情绪，但不为了“像个人”而硬塞语气词。
- 使用“一、二、三”和“1. 2. 3.”这类直接层级，少造概念、少用系统化黑话。
- 段落有长有短，允许“先看效果”“这里可要可不要”“到这里就完成了”这种自然转场。
- 配图不是装饰窗，而是每隔一段距离帮读者看到效果、步骤或差异。
- 保留一点不完全整齐的人感。不要每章字数一样、每节都同样收束、每张图都按同一公式出现。

反向检查：如果去掉内容后，只剩下一套工整的栏目名和卡片，就太像 AI 模板了。

## 4. 标准文章骨架

这是可选素材库，不是每篇都要走完的流程：

1. 封面或开篇导语。
2. 内容导读，精选三个核心看点。
3. 前言正文。
4. `01 / 观察`：问题与现象。
5. 水墨隐喻图：把核心矛盾变成词员外的动作。
6. `02 / 衡量`：变量、方法或判断标准。
7. 事实核验、尚待确认、常见误区等内容卡。
8. `03 / 总结`：结论、边界和可复用方法。
9. 核心观点、员外一句或强调结论，三选一作为最强收束。
10. 全文总结。
11. 作者说明与互动区。
12. 尾部朱砂印。

目录不是完整章节清单，只展示三个最重要的阅读收益。

## 5. 视觉层级

### 锚点层

全文不超过 4—5 处：水墨认知隐喻图、核心观点、深墨结论、强调结论、最终 CTA。

### 标记层

正文每段选择 1—2 个关键短语，用朱砂下划线标记。不要整句划线，不要每个名词都强调。

### 容器层

事实核验、尚待确认、核心结论、常见误区、步骤卡等按语义使用。普通文章建议只选 1—2 种容器，教程长文最多 3 种。大部分内容应该仍然是正文、小标题和图片，不要把全部卡片轮流展示。

## 6. 词员外出场规则

词员外不是头像挂件或每个标题旁的吉祥物。他在需要视觉解释时是内容的解释者，其余时间让位给作者本人和内容。

必须满足：

- 词员外承担画面核心动作；去掉角色后，隐喻应明显失效。
- 折扇“词员外”和朱砂印“词元”优先保留。
- 一张图只解释一个认知动作或结构。
- 主体占画面约 40%—60%，至少保留约 35% 安静区域。
- 图中文字控制在 5—8 处以内，每处尽量 2—8 字。

文章出图建议：

- 短文：1—2 张。
- 普通长文：3—5 张。
- 超长教程或专题：最多 6—7 张。

不要每一章都机械放一张人物图。优先选择核心判断、认知转折、输入输出关系、前后对比和常见误区。

## 7. 文章类型配方

### AI 原理与行业观察

核心：现代正文 + 数字章节 + 核心观点 + 水墨概念隐喻。  
点缀：事实核验、尚待确认、数据指标。

### 方法论与知识管理

核心：内容导读 + 三层结构 + 步骤卡 + 核心结论卡。  
点缀：任务清单、补充说明。

### 工具测评与经验复盘

核心：调整前后对照 + 两案对照 + 常见误区 + 全文总结。  
点缀：时间线、指标、纸页代码块。

### 教程与操作指南

核心：步骤卡 + 执行流程 + 检查清单 + 纸页代码块。  
点缀：完成状态、待补素材。

### 个人思考与长期主义

核心：极简文字封面 + 现代正文 + 水墨隐喻图 + 核心观点。  
点缀：补充说明、墨点分隔。容器数量应更少。

## 8. 代码与技术内容

代码仍然保留，但降低“科技控制台”的存在感：

- 默认使用暖灰纸页代码块。
- 只有命令输出、错误日志等场景使用深墨代码块。
- 技术名词用轻量行内代码标签。
- 不把普通概念硬包装成终端 UI。

## 9. 图像展示原则

图像生成由独立的 agent / skill 负责，本主题只处理已有图像如何进入公众号文章。

默认提供四种展示方式：

| 图像类型 | 展示方式 |
|---|---|
| 普通插图 / 截图 | 正文宽度内居中，4—6px 小圆角，上下留白 |
| 核心概念图 / 流程图 | 可通栏展示，不叠加卡片文案 |
| 有原文图注的图 | 图下方居中小字图注，用中性灰 |
| 两张前后对照 | 用统一间距和极细分隔线组织，不增加多余装饰 |
| 同组 3 张以上图片 | 横向滑动收纳，只占一张图左右的页面高度，并露出下一张一小部分 |

处理纪律：

- 不调用生图或修图能力。
- 不改变图片内容、比例和顺序。
- 不给每张图都套“精致卡片”；有些图只需要留白。
- 不自行编造图注、图片结论或图内文案。
- 大图自适应缩小，小图保持原尺寸，避免被拉伸变糊。
- 边框与阴影的优先级低于留白。只在截图与背景难以区分时，使用 1px 暖灰细线。

### 内容收纳组件

参考阿真文章中“滑动查看完整提示词 / 长图”的处理方式，但只借用交互逻辑，不照搬其紫色视觉：

- 同一逻辑组的 3 张及以上图片放入横向滑动组，默认卡片宽度约 86%，右侧露出下一张，明确提示“左右滑动查看”。
- 两张图若承担前后对照关系，继续上下或并排展示，不为追求横滑而破坏比较阅读。
- 长 Prompt、操作记录、配置说明和补充材料超过约 12 行或 500 字时，放入 240—320px 的定高窗口，默认 280px，在窗口内部上下滑动。
- 普通文章正文、关键结论和连续论证不收进滚动窗；滚动组件是为了降低页面占用，不是为了把内容藏起来。
- 滚动窗口中的文字必须保持为可选择、可复制的 HTML 文本，不能截成长图代替。
- 组件只使用原生滚动，不加脚本轮播、自动播放、分页圆点或复杂按钮，确保复制进公众号编辑器后稳定。

## 10. 封面原则

封面采用“现代编辑标题 + 单一水墨认知动作”，而不是人物立绘海报。

建议比例：

- 标题与选题信息：55%—60%。
- 词员外隐喻场景：30%—35%。
- 栏目、期号和品牌印章：约 10%。

封面上的词员外也必须在做事，例如称量、归档、分流、盖章、搬运或连接，不能只是看镜头。

## 11. 当前交付边界

当前阶段已经完成完整主题预览，并补充横向多图与长文本滚动两类内容收纳组件，覆盖封面、标题、正文、引用、提示、列表、流程、媒体、代码、数据、FAQ、作者、CTA 和结尾。

本轮先不把主题登记为正式主题。确认整体气质后，再执行：

1. 从完整预览 Block 中精选 20—35 个正式组件。
2. 转换为 `references/theme-ciyuanwai-ledger.md`。
3. 补充正式文章骨架、文章类型配方和 Markdown 映射。
4. 登记进 `theme-index.md`。
5. 跑组件源头检查至 0 ERROR。
6. 用一篇真实文章生成公众号 HTML 做最终验证。
